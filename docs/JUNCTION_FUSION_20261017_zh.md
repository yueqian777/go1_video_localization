# 路口融合与历史路段重组（2026-10-17）

## 本轮实现了什么

在现有 `codex/evidence-viser-route-preview` 分支增量实现，开发基线为 `7d519b8220eacc3eed662b43e06c899834ec5980`。继续使用既有 hloc / SuperPoint / LightGlue / PyCOLMAP、冻结地图、照片目标证据、Viser 和 Dijkstra。

例如，历史记录分别为 `A → J第一次 → C` 和 `D → J第二次 → E`，在确认两次 J 属于同一个小范围位置后，可以组合 `A → J → E`，不需要原录像完整走过 A 到 E。这里确认的是地图中的重复位置几何，不是现场通行认证。

本轮只在**同一冻结地图、同一注册分量**内连接历史段，不自动配准不同地图，不提供跨地图拼接，也不增加多视频导入架构。原节点位姿、历史折线、时间断点与有向边不被改写。重组只沿记录过的路段切换，不生成穿越未知空间的捷径。

所有输出均为相机路线/方向预览，`execution_permitted=false`。没有连接 Go1、读取实时相机或发送运动命令。地图没有米制尺度时继续使用 `map_units`。

## 网页操作

1. 使用原桌面快捷方式打开工作台，加载最终地图。已有地图来源声明会自动读取；首次使用仍需声明真实采集方式和相机安装情况。
2. 在“开始找物与方向引导”中展开“路口融合与路线重组”。加载地图或保存一次性设置时，自动生成含路口连接的新索引，不用逐段点确认。
3. 查看自动采用数量、证据不足数量及重复停留观察数量。选择连接，点击“查看这个连接的两张历史照片”，可以对照两次经过的画面。
4. 延续既有当前照片/独立回放和框选目标流程。当前观测实际定位成功后，Dijkstra 会在原历史段与通过证据检查的连接之间选择路线；采用重组时显示连接数量。
5. 对连接有疑问时，可在正在进行的引导任务中点击“本次任务停用此连接并重新规划”。它会关闭这一连接的两个切换方向，撤销旧引导，等待新观测重新规划；没有替代路线会报告无路。停用不修改原地图，只影响当前任务。

最终地图连接不会叠加到未对齐的建图快照。切换地图/快照会清除旧连接；旧后台任务不能覆盖新地图的索引，关闭查看器后也不能发布迟到结果。加载目标不会错误撤销只针对地图的索引准备任务。

## 连接证据与局限

距离近只产生候选，不能单独形成连接。当前保守默认阈值为：

- 同一地图哈希、分量、原生参考位姿；不同已知物理相机不直接连接。
- 距离不超过局部采样间隔的 0.35 倍，高度差不超过 0.10 倍；局部尺度不超过全图典型步长。
- 相机上方向差不超过 20°；排除相距不超过三条时间邻接边的普通相邻观察。
- 至少 15 个共同三维轨迹，占较少一侧有效轨迹至少 20%；正深度、每帧重投影误差不超过 3 px。
- 共同特征在两幅图中都具有足够二维分布，而非集中在一个小区域。
- 两侧各至少一个有效时间邻居具有不少于 8 个共同轨迹支持。

证据直接从已校验的原生 PyCOLMAP 重建读取，包含真实观测、重投影误差、图像坐标、深度与位姿，不额外运行或替换视觉特征算法。缺失/冲突证据保留拒绝原因。

每个连接保存独立证据摘要和哈希，加入带正代价的双向“切换历史经过”边；不会自动把全部原历史路段改成双向。相机节点不合并、不平均，也不凭 A-B、B-C 接近就直接补 A-C。原拐角保留，零长度切换不能使前视点越过拐弯。

这些阈值属于启发式几何约束，不是误连接概率保证。相似走廊、窄隔墙、视角相反但缺共同轨迹、尺度漂移等情况仍需真实复杂场景验证。没有地面/占据/机器人外形信息，不能据此证明通道净空和机器人可通行性。
