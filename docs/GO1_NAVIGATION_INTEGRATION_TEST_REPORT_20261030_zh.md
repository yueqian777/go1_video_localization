# Go1 导航控制跨仓库集成测试报告

日期：2026-10-30
范围：`go1_video_localization` 与 `go1_remote_control` 的离线集成修改

## 结论

本轮把视觉导航的运动请求改为有限期的运动意图。控制服务内部以固定周期续发，直到该意图自己的截止时间；机器狗接收端仍保留更短的 MOVE TTL。运动中的合法动作可以续租，但暂停、失联、失权和任务过期不能靠续租恢复运动。视觉定位暂时不可用时，导航进入 `WAIT_RELOCALIZATION`，清除当前非零运动意图并保留可恢复任务；定位恢复后必须依据当前位姿重新规划，不能重放旧动作。

本轮没有连接真实 Go1，没有发送真实运动指令，没有自动 TAKE 或 ARM，也没有新增 Unitree SDK 控制连接。A* 路径生成和已有运动限幅保持不变。

## 已实现的契约

| 层次 | 机制 | 当前离线实现 |
| --- | --- | --- |
| 网络 | 状态反馈新鲜度 | `NETWORK_TIMEOUT_S=3.0s`；失联后停止续发并关闭连接 |
| 人工控制 | 浏览器按键租约 | `UI_LEASE_S=0.5s`；人工 STOP 和手动接管优先 |
| 自动运动 | 运动意图 | 默认任务动作有效期不超过 `2.0s`，调度周期 `0.05s` |
| 接收端 | MOVE 死人开关 | `RECEIVER_MOVE_TTL_S=0.6s`，与 PC 任务租约独立 |
| 任务 | 自动导航授权 | 默认 `3.0s`，看门狗主动过期，不依赖状态页面请求 |
| 暂停恢复 | 任务恢复窗口 | 默认 `5.0s`；暂停没有有效非零速度，恢复不重放旧命令 |
| 视觉 | 定位恢复 | `WAIT_RELOCALIZATION -> RESUMING -> REPLANNING` |
| 反馈 | 因果链 | 意图 ID、PC 发送序号、接收端命令序号、运动开始/停止时刻、相机采集时刻和时钟不确定度 |
| 执行门禁 | 标定证据 | `CalibrationEvidence` 要求米制尺度、重力、相机外参、地图朝向和证据 ID |

暂停时会发送零速度 STOP，但保留任务租约和接收端会话；真正的人工 STOP、网络失联和任务过期会撤销导航权限并清除会话保持。接收端能力版本不匹配时，旧程序仍可用于人工遥控，但导航授权会被拒绝。

完成一个运动原语的判据已经与 HTTP 状态读取时间分开：PC 只把状态读取时间记为“反馈到达”，用接收端单调时钟映射记录运动开始/停止；相机采集时间必须晚于停止事件并落在可比较的时钟域内。PnP 计算完成得晚，不能使运动前采集的旧图像成为完成证据。直行还必须看到实际位置变化，转向必须看到新的有效朝向。

## 跨仓库模拟流程

`tests/test_cross_repo_navigation.py` 使用控制仓库中的原生模拟接收端、PC HTTP 服务和视觉仓库的 `NavigationHttpClient`，覆盖以下实际链路：

1. 连接模拟接收端并建立已授权控制会话。
2. 视觉端授权任务并提交带 TTL 的转向请求。
3. 从 PC 服务状态转换出视觉闭环所需的 Telemetry，区分命令已接受、正在执行和已停止。
4. 暂停导航，确认当前运动意图被清除且任务仍保留。
5. 恢复任务，确认恢复阶段不会产生旧动作。
6. 提交新的前进请求，等待有限期意图自然过期并确认过期计数增加。
7. 发出 STOP，确认控制链路归零。

此外，控制仓库的权限测试覆盖了旧任务争夺、整任务命令 ID 去重、健康状态拒绝、暂停/续租/恢复和 HTTP 接口；接收端策略测试覆盖六个方向、MOVE TTL、STOP、健康门、状态漂移和延迟 ACK。

## 体验指标的离线判定

- 连续同方向前进动作会合并，默认最多合并 3 个栅格；转弯、障碍和目标附近仍保持单动作边界。
- 视觉间隔为 `0.5s` 时保持动作执行；超过当前定位新鲜度后进入等待重定位，不销毁任务。
- 暂时失去定位、局部避障停顿和较慢模型计算都会先输出零速度等待。
- 定位恢复后必须用新帧和当前位姿进入重新规划，旧命令 ID 不会再次执行。
- 控制反馈为 `executing` 时保持执行态，不把“尚未停止”错误标记为终态故障。
- 网络状态失联时不再续发 MOVE；接收端短 TTL 仍提供最后一道停止保护。
- 运动期间连续 3 次 keepalive 都保持同一合法任务和命令 ID；STOP、网络失联和任务过期分别进入不同的停止路径。
- 接收端已收到 MOVE 但尚未进入运动状态时，闭环只保持等待，不宣布完成；已停止但相机仍是旧帧时同样不能完成。
- 暂停恢复后必须产生新命令 ID；旧命令不会被重新提交。

## Runner 使用边界

默认启动只做 SHADOW 观测：

```powershell
$env:PYTHONPATH = "src"
python -m go1loc.navigation_runner --mode SHADOW
```

`SIMULATION` 只能接收模拟接收端，并复用已有控制会话；`LIVE_SUPERVISED` 还需要操作者单独授权、接收端新版能力集和与导航器一致的 `CalibrationEvidence`。Runner 初始化和启动阶段不会自动连接、TAKE、ARM 或提交非零动作。现场执行前仍需由操作者单独完成站立、接管和急停准备。

## 仍需现场验证的参数

以下内容没有在本轮离线测试中替机器狗定标：Go1 实际速度字段的单位和坐标系、实际 yaw rate 噪声、视觉定位耗时分布、相机与接收端时钟偏移及不确定度、每个栅格的真实步态距离、转向完成判据、障碍步态下的偏移阈值，以及 `0.6s` 接收端 TTL 与具体固件的兼容性。短时位姿预测已经实现为有界辅助函数，但仍应使用录像和遥测时间戳标定后，再决定是否在现场闭环中启用。
