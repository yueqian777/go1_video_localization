# 新相机录像网页建图与路线预览

日期：2026-10-16。基于功能分支 `codex/evidence-viser-route-preview`，基线 `b6694c1` 增量修改。

## 日常操作：不需要 PowerShell

1. 打开桌面「Go1 地图与照片定位」快捷方式。
2. 在页面「新建地图」区域，点击「刷新本机录制记录」。
3. 选择新相机的录像记录（来源 `orbbec_rgb_mjpeg`、相机6、1280×720），点击「使用选中记录建图」。这是选择已有文件，不是启动相机。
4. 等待原尺寸首帧和来源核验完成。系统直接读取 `data/captures` 中已结束录像的 PNG、帧序号、读取时间和哈希，无需先导出 MKV。单张快照、未完成/中断录像不进入这个简易入口。
5. 初次建议处理30秒、间隔0.5秒。没有实测标定可先不选；系统不会自动套用旧鱼眼标定或重复去畸变。
6. 检查画面，勾选确认，点击「开始建图」。后台运行、阶段提示、真实 READY 快照和完成后的冻结地图沿用现有流程；可以暂停跟随、回看历史快照。
7. 建图失败时保留原素材、质量记录与失败原因，不伪造点云。成功后可按视频顺序播放照片，并继续目标定位、路段审核和路线预览。

也可点击「选择视频 MP4 / MKV」。上限512 MiB。上传的原始字节与扩展名保留，按哈希验证后解码，**不是把MKV改名为MP4**。普通文件默认按单路视频处理；如果是带界面的屏幕录制，请明确切换为「Go1 界面录屏」并检查裁剪/掩膜。

直接上传单个视频容器无法恢复它没有携带的原生录制身份、帧读取时间和相机标定。要保留新相机的完整来源，请优先选择原始录制记录，不要把普通视频强行标记为原生相机数据。

## 可选实测标定

先选择素材并等待首帧，再展开「相机实测标定」，上传当前相机对应的独立 JSON（≤64 KiB）。更换素材会清掉旧标定选择；更改标定需要重新确认预览。可以明确移除标定。

沿用项目标定格式：`source`、`model`、`image_size`、`K`、`distortion`、`output_size`、`output_K`（可选）、`map_version`。支持 `opencv` / `pinhole` 与 `fisheye` / `opencv_fisheye`。不能用虚构内参、旧相机参数或别的分辨率凑数。

原始录制还需要以下绑定：

| 字段 | 含义 |
| --- | --- |
| `capture_camera_id` | 录像中的相机编号；当前RGB通道为6 |
| `capture_source_kind` | 当前录像的来源，新RGB通道为 `orbbec_rgb_mjpeg` |
| `capture_camera_serial` | 录像元数据中记载的实际设备序列号（有记录时必须一致） |
| `capture_projection` | `raw_pinhole`、`raw_fisheye` 或 `rectified_pinhole` |
| `projection_evidence` | 原始投影未知时，说明凭什么确认标定适用于该视图 |

普通MP4/MKV标定使用 `input_projection` 与 `projection_evidence`，由网页选择动作绑定到当前视频哈希。它是用户提供的标定，不是程序自动测得的标定。

已去畸变输入不得再应用非零畸变参数。原始元数据中的未知投影不会被改写，采用的标定投影另存于几何记录中。网页不跟随标定JSON中的外部文件路径；独立有效区域来自标定映射及其裁剪。

标定不自动提供米制尺度。没有额外尺度证据时，地图和路线长度仍是 `map_units`。

## 路线：全局路线与局部避障分工

已有地图后，按页面顺序完成：目标照片求解 → 选择人工历史起点（或合法接入的独立照片起点）→ 审核连续路段 → 保存路线图 → 计算路线。

新增功能：

- 「按机载局部避障可用的前提预览」：记录使用假设，不读取实机，也不声称避障已经打开。全局路线仍沿已审核历史连接求最短路径，不要求证明沿线每一处当前都空旷。
- 「路段封闭与重新规划」：读取路段，选中想排除的有向边，点击「本次避开这条路段」，再计算。不会修改冻结地图或原始路线图；没有已知替代连接时返回 `no_path`，不能用隔墙直线代替。
- 「路线摘要与途经点」：显示目标观察帧、累计长度、途经参考帧和三维折线转角。转角不是机身偏航指令；未确定重力方向时不虚构“左转/右转”。

机载局部避障不能替代地图连通性、定位可信度或相机到机身的外参。所有结果继续 `execution_permitted=false`，没有运动执行、自动避障部署、自由空间规划或Nav2。

新相机来源现在可以生成待审核候选路段，**不会自动勾选连续性**。源帧中断、未注册帧、时间缺口及分量变化仍是审核边界。时间是 `agent_read_monotonic_not_exposure`，不是曝光UTC；不能把它伪装成现实当前照片的采集时间。

## 本轮真实录像结果与缺少的数据

已有新相机录像已通过网页服务端按钮回调进入真实建图流水线。前30秒抽取57帧，57帧通过默认清晰度筛选，完成SuperPoint提取及270对LightGlue匹配，但PyCOLMAP未找到合适初始图像对，因此没有生成地图。

抽查首帧、约15秒和约30秒时视角几乎不变。500个跟踪点相对首帧的中位像素位移分别约0.052和0.078像素。这是二维图像变化诊断，不是机器狗位移、标定精度或定位成功率；结合画面和重建日志，符合基本静止录像缺少视差的情况。

需要补采：一段有缓慢平移、视角连续重叠的真实录像，建议先30–60秒，避免只站着不动或原地转圈。随后再提供未参与建图的独立目标/当前位置照片。当前没有新相机实测标定，也没有新相机真实路线A/B验收结果。

## 验证与复现

本地验证输出：`results/rgb_web_mapping_20261016/`。

- `progress.json`：真实任务阶段变化。
- `failure.json`：实际重建失败，不冒充成功。
- `motion_diagnostic.json`：首/中/末图像位移诊断。
- `viewer/web_build/worker/jobs/*/worker.log`：特征匹配及PyCOLMAP原始日志。
- `viewer/web_build/worker/jobs/*/output/prepared/frames_manifest.json`：原生来源、哈希、原帧序号及读取时间。
- `final_tests/unittest.log`、`summary.json`、`coverage.json`：软件回归记录。

已有全部本地测试418项通过、无跳过；针对本次五个相关模块的行覆盖约92.6%。这些是软件回归数字，不是定位成功率。普通相机标定与路线成功/断边由明确标记的合成夹具验证，不能替代真实路线验收。已验证服务端UI回调、后台任务和原尺寸图像，未把它称为浏览器截图验收。
