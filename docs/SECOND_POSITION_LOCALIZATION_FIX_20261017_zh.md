# 第二位置定位失败：离线诊断与参考图一致性修复

## 结论与边界

本轮只处理保存的数据，未连接camera6，未发送机器人运动命令。基于功能分支 `codex/evidence-viser-route-preview` 的 `e4f00a47843b405c4cb35569cac3dbeba44bf9eb` 增量修改，沿用原地图、白球结果与视觉模型。

第二位置原来18张照片均因PnP质量不足被拒绝。已复现的软件机制是：没有全局检索描述子的这张小地图会匹配全部58张参考图；连续轨迹的传递共视关系把它们合成一个大簇。当前画面与远处/较差视角参考图的冲突对应一起进入PnP，使原始2D–3D对应数膨胀，内点比例低于门槛。不是只因断网、延迟、旧局部缓存或固定错误焦距。

修复为有界的**查询参考图一致性回退**，不改变SuperPoint、LightGlue、PyCOLMAP，不改冻结地图或PnP门槛。第二位置已完成保存匹配重算、原始PNG重新提取匹配两种验证；这是历史观测离线重新计算，**不是新的实机成功，也没有位置真值来证明精度**。

定位恢复不等于路线恢复：第二位置仍超出历史路线接入范围，保持 `off_route`，没有到白球的方向。实际偏离历史路线、地图局部几何误差和相机未标定误差的贡献仍未区分。本轮没有为了给出方向而扩大接入倍数。

## 2. 实际修复

修改集中在 `src/go1loc/localization.py`：

1. 原共视簇已通过质量检查时沿用原流程，不追加回退估计。
2. 所有原候选均不合格时，按实际映射匹配数排序，最多检查现有 `top_k=20` 个参考；不使用目标位置或人工XYZ选参考。
3. 每张参考独立PnP只能作为假设，不能独自恢复定位。
4. 同一共视簇内两个假设须互相解释对方至少一半的有效内点，且每方向至少满足现有最小内点数；重投影仍为4px。查询特征按索引去重计票。
5. 额外要求旋转差≤5°、相机中心差≤可见深度中位数的5%、焦距比≤1.25，用于排除仅在图像平面相似的焦距/深度退化。不依赖米制尺度或 `typical_step`。
6. 每个种子只尝试其最强一致伙伴，重复参考对不重复计算；对该参考对的**所有原始对应**重新PnP，不仅使用其内点，不将分母裁成内点数。
7. 联合结果仍须通过原阈值，并与两个种子一致。强度相近但不一致的解返回 `ambiguous_reference_consensus`；不同共视分量不能因XYZ碰巧接近而去重。
8. 证据保留原大簇、回退假设、候选相机与位姿、完整对应、种子关联及选中结果。原图身份、原图/特征/匹配文件哈希继续核验。

这些是**参考选择策略改变后的质量检查**，不是在同一分母上证明准确率增加。新一致性门槛在批量回放前冻结，没有随着个别失败样例增大。生产原阈值仍为最少6个2D–3D/内点、内点比例0.25、RANSAC误差4px；路线接入2倍/跟踪2.5倍步距、3秒新鲜度也未改变。

必须分开理解：

- `cached_matches`：核验原图及证据后，只复用保存的SuperPoint/LightGlue结果，重新运行PnP和选择；用于隔离软件机制。
- `saved_images`：从原始PNG重新提取、匹配、求解，按原顺序用一个常驻后端更新局部参考缓存；不是从旧结果复制位姿。
- `offline_replay`：保存原收帧时钟/来源元数据、实际本次运行时间；传感器曝光时间未知仍为null。历史照片没有被伪装成当前帧。
- 路线/方向统计只检查保存数据的离线状态逻辑；现场用户当时未观察方向正确性，因此不能称为方向正确率。

## 4. 使用与复现

网页流程不变，启动原桌面工作台、加载同一地图与目标后使用。无需重建地图、修改旧查询或重装环境。只有用户明确安排现场复测时才连接camera6；本轮停掉了已暂停/断开的旧工作台，以释放旧常驻模型，避免并行第二套GPU定位器。

项目根目录中可执行（输出目录需新名称）：

```powershell
& '.\runtime\python312\python.exe' -X utf8 -m unittest discover -s tests -p 'test_localization*.py' -v
& '.\runtime\python312\python.exe' -X utf8 tools/run_live_navigation_tests.py --output results/second_position_offline_20261017/regression_new

$mapPath = 'results/screen_import_20261014/viewer_zh_20261015/web_build/worker/jobs/3caa15ce7b1c4b45ae10f8c221dbefa5/output/map'
$taskPath = 'results/workbench_integration_20261017/viewer/navigation/task-a4263c5b42b14066a0200ac4bca09039'
& '.\runtime\python312\python.exe' -X utf8 tools/replay_saved_localization.py --map $mapPath --task $taskPath --mode cached_matches --output results/second_position_offline_20261017/cached_new
& '.\runtime\python312\python.exe' -X utf8 tools/replay_saved_localization.py --map $mapPath --task $taskPath --mode saved_images --output results/second_position_offline_20261017/images_new
```

该回放工具限定已有原生、未去畸变的任务记录；遇到标定/录屏派生输入显式拒绝，不默默忽略几何变换。不会开启采集或运动接口，所有路线结果 `execution_permitted=false`。每次新目录写参数、源码哈希、版本、逐条结果和summary；原记录不覆盖。

## 5. 下次何时需要现场配合

本轮离线修复不需要用户继续控制机器狗。后续需另约一次新编号验证：

1. 先在起点静止，确认预热后最新位置显示及处理时效。
2. 用户遥控到第二位置附近的已知历史视角，停住，核对实际相机方向/安装和对应历史画面；确认显示位置与现场是否一致。
3. 如位姿仍明显偏离历史路线，采集可验证相机标定或局部更多视角来区分地图/相机误差与真实路线偏离；不手填XYZ、不扩大接入倍数。
4. 只有定位和合法接入都稳定后，继续实际转角、到白球观察区、断流/封边等影子引导验证。

机器人仍由用户遥控。真实运动适配器、米制尺度/相机到机身外参、闭环状态反馈/接管和实测避障接口仍未接通，不包含在本次修复中。
