# 网页选片建图交付记录 · 2026-10-15

基于功能分支 `codex/evidence-viser-route-preview` 的 `4990855` 增量实现。没有更换 hloc / SuperPoint / LightGlue / PyCOLMAP，没有安装环境，也没有连接机器狗或发送运动命令。原生快照、照片证据、路线审核、时间语义与图片回放继续使用。

## 用户入口

双击原桌面快捷方式，或刷新本机 `http://127.0.0.1:8767/`。页面顶部展开“新建地图：选视频 → 开始 → 看进度”：

1. 选择 MP4；网页实际提交首帧解码任务，显示原始尺寸与视频长度。
2. 确认来源、裁剪及排除区域；几何未知时不额外去畸变，不编造相机编号。
3. 设置片段长度与抽帧间隔，勾选检查确认，点击“开始建图”。
4. 同页看真实阶段和完整快照，成功后自动显示新地图。可暂停跟随、看历史快照、返回启动地图。
5. “① 地图”的全程图片回放直接用于新地图；路线与定位仍保持原有证据门槛。

具体操作见 `NEW_VIDEO_AND_PLAYBACK_zh.md`。高级命令操作单仅作备用，不是新流程的必要步骤。

## 实现和保护措施

- `web_build.py`：上传原字节副本、哈希关系、输入校验、独立任务目录；固定 worker 入口调用现有 `prepare_video` 与 `build_map`，没有 shell 拼接。
- `web_build_ui.py`：中文向导、原尺寸首帧、矩形排除编辑与有效区域诊断、任务监看、地图交接。Viser 仍只监听本机回环地址。
- `jobs.py`：增加固定的 `inspect_video` / `build_video` 两种任务；未开放任意命令或动态导入入口。
- `viser_viewer.py`：沿用既有显示逻辑接入真实建图快照；跨任务退休旧目标、起点和路线；延迟完成的旧地图任务也不能回写新场景。
- 默认严格质量过滤。只有显式选择低质量探索才放宽过滤，并在界面和保存参数中标注。少于两张有效帧不启动建图。
- 原录屏、旧冻结地图、公开照片实验和旧回放记录没有覆盖。每次建图使用新 UUID 目录；失败保留日志、质量资料和已有快照。
- 不读取活动中的半写入模型；快照仅经现有 run / READY 校验器与 worker 原生解析后显示。快照、重建分量与最终地图不未经对齐叠加。
- 刷新浏览器不取消任务。重新打开同一入口恢复最近任务；并未新增自动重算、模型下载、导航或机器人执行。

## 验证范围与剩余限制

测试驱动补充了上传约束、来源哈希冲突、输入预算、旧结果保护、重复提交、暂停跟随、失败保留与恢复检查。314 项测试通过不是定位成功率；代码覆盖率也不是重建精度。

实际使用真实 Viser 服务、服务端控件回调、独立计算进程及原生模型验证了闭环。浏览器自动化此前被安全策略阻止，没有绕过；本轮没有浏览器渲染截图或自动文件选择器点击验收。应刷新实际页面检查布局，不能把服务端记录称作网页截图。

网页文件上传沿用 Viser 的整文件缓冲机制，512 MiB 是接收后的大小检查，不是流式上传或内存占用保证；大素材建议先录制较短试片。浏览器与后台应用共享任务状态；本轮没有新增多用户隔离。关闭网页不取消计算，也没有强杀后台任务按钮。操作系统强制终止 worker 后，运行中状态可能需要人工诊断，不会静默自动重算。

工作区其他网络采集模块存在并行未提交修改，予以保留，不纳入本轮提交。真实试片在当前工作区执行；这些并行来源扩展不改变本次 `go1_screen_recording` 处理分支。没有上传原视频、私人图片、地图文件或模型权重。
