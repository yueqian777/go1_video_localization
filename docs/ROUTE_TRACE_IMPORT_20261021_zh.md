# 连续实测路线支路导入

## 目的

当前冻结地图只包含建图录像中实际注册的相机轨迹。实时画面已经定位成功、但明显偏离旧路段时，不能把最近历史边或最近节点直接当成当前位置的路线接入。`navigation_trace.py` 增加了一个独立的 sidecar 机制：把另一段真实录像中逐帧定位通过的连续观测作为有向相机路线支路导入。

它不会改写 `map_manifest.json`、COLMAP 模型或旧的 `navigation_index.json` 归档，也不会启用运动执行。每个新增节点都保存查询哈希、证据哈希、源录像身份、序号和读帧时间；证据缺失、来源冲突、质量不够、超过 0.5 秒的观测间隔或位姿跳变都会拒绝形成边。

## 路线接入规则

- 支路内部只连接真实、按源时间递增的定位观测；不插值、不补 XYZ。
- 可选的 entry/exit 锚点必须先由现有 `associate_route` 得到合法历史边关联；投影点由历史边和 fraction 重新计算，sidecar 中的 XYZ 只能作为一致性检查。
- 锚点前后必须各有不超过 0.5 秒的真实观测；不能只凭空间近邻连接。
- 反向路线不会自动增加；新增边保留实际观测方向，全部 `execution_permitted=false`。
- 没有合法锚点的连续段可以保留用于诊断，但仍是孤立段，规划器会返回 `no_path`。

## 当前第二位置保存数据

`ROUND_TRIP_ROUTE_DIAGNOSIS_20261018_zh.md` 中的第二位置样本显示：45 帧定位通过，但均距离旧路线约 1.11–1.60 `map_units`；10 帧因参考一致性歧义未采用。该区间的保存分析不是逐源帧连续结果，存在超过 0.5 秒的采样间隔，且区间前后没有同一份分析中合法关联的锚点。因此本轮不会把这 45 帧强行接到旧路线；它们应作为“已定位、路线证据不足”显示。

新机制已用带 entry/exit 证据的连续真实观测夹具验证。要让第二位置成为可规划支路，需要从该位置前的实际行进开始重新采集并保存连续的 camera6 画面，覆盖离开旧路段、第二位置和返回/重新接入点；程序仍不会发送运动命令。

## 运行时

`navigation_io.prepare_index()` 会在地图对应的导航 sidecar 中发现 `route_trace_import.json` 时自动核验并载入；没有该文件时现有地图流程完全不变。导入文件只引用已保存的定位证据目录，姿态从 `localization_result.json` 读取，不能手填姿态。
