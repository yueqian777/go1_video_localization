## 原因和修复

### 无窗口启动

`pythonw.exe` 下标准输出/错误可能是 `None`，hloc 初始化模型会调用 `sys.stdout.flush()`。只有 logging 文件处理器并不能提供标准流。

`capture_desktop` 现在仅为缺失的标准流提供日志适配器，控制台已有流保持不变。适配器直接交给轮转日志处理器，不递归调用根日志；退出时恢复原流。异步模型错误保留具体原因，不再被“照片缺少环境细节”覆盖。

复核视频证据又触发另一项无窗口问题：FFprobe 子进程退出码 `3221225786`，没有错误文本。最小测试中继承控制台或只改 stdin 均失败，使用 `CREATE_NO_WINDOW` 后退出码为0。视频探测和解码现在显式使用后台进程及 `DEVNULL` 输入；不安装或更换 FFmpeg。

### 位置显示与路线分离

此前 UI 与统一工作台只把 following/turning 等路线状态视为有当前位置。实际 PnP 成功但 off_route 时，位置也被隐藏。

统一使用 `NavigationTask.current_pose_available()`，检查证据、地图/分量、合法刚体位姿、来源状态和新鲜度，不要求规划成功。过期等失败同时清理旧计划。界面明确显示“当前位置已定位 · 路线尚未接入”。路线接入距离没有放宽。
