# 自动路线与视觉方向引导（2026-10-16）

本轮基于 `codex/evidence-viser-route-preview` / `8fe52b0` 增量修改。
没有重建旧地图、改装主视觉环境、安装新导航模型或连接运动控制。

## 如何使用

1. 使用原桌面快捷方式打开工作台；新建地图操作收在折叠区。
2. 首次使用某地图，在“首次使用”中声明真实采集方式，确认所选相机固定朝前、画面正立。
   camera6 和 camera1 分开保存。白球地图与 camera6 的声明已经按用户本轮回复保存到本机 sidecar。
3. 选择“已开启的本地相机”或“独立录像回放”。前者只读取本地录制台已有画面，**不代替用户启动 SSH 采集**；没有画面会解释原因。
4. 上传目标照片 → 打开原图 → 鼠标画框 → 计算。已有成功白球目标可以继续使用。
   也可在任务开始前点击“取一张当前画面作为目标照片”，从已开启的本地相机读取一张新图；断流时保留原目标并说明原因。
5. 点击“开始方向引导”。不必选历史精确起点、填写 attachment JSON 或逐边审核。
6. 根据实际当前图和下一参考图，用遥控器行走。可随时暂停、取消或封闭当前路段。
   本程序不发送运动命令。橙色相机表示测得的当前相机，绿色为目标观察位姿，青色为历史路线。

只有观察区附近的新图复现目标支持特征，才会显示“新画面已复现目标几何证据”。
这是几何复现，不是语义识别保证、精确球心或“自主导航成功”。旧照片不能证明目标现在仍在。

原人工起点、路线审核、独立观测身份检查及 JSON 导入仍在“显示研究模式与旧流程”中，合同未放宽。

## 本轮新增的实现

| 内容 | 实现与边界 |
|---|---|
| 自动路线 | `navigation.py`：只从同分量、同来源、时间相邻的真实参考序列构图；标注 automatic_recorded_traversal，不伪造人工 verified_continuous |
| 两层路线 | 保留每段参考折线与粗导航节点；转角保留，静止转身标 observation_only；前视跨度可配置并在转角截断 |
| 接入 | 实测 PnP、参考帧支持、偏离距离、朝向与序列共同关联；允许路段中间起点；大范围分支跳变需第二次观察 |
| 搜索 | 复用 Dijkstra，综合路线长度、边观察质量、目标观察质量与封闭状态；不是空间近邻连线 |
| 目标 | 核验原图/ROI/查询证据，再从实际支持轨迹、图像分布筛选观察位置；不把物体表面点用作机身终点 |
| 常驻定位 | `navigation_localizer.py`：SuperPoint、LightGlue、冻结模型、参考特征常驻；附近参考子图优先，失败后全局重定位；沿用原 PnP 及焦距策略 |
| 最新帧 | 一个正在计算的帧＋一个可替换的待处理帧；任务代际隔离；旧帧、断流、暂停、取消都撤销方向提示 |
| 时间 | 回放保留源读取时间、原接收时间、独立回放会话和实际运行时间；曝光未知仍为 null；不要求每次手填时间 |
| 当前相机 | GET-only 读取 localhost:8772 已有采集页；不启动相机或运动接口；明确这是 PC 预览接收时间而非曝光时间 |
| 数据独立性 | 文件哈希＋解码像素哈希；原录制重新编码成 PNG/MKV 后仍不能冒充独立回放 |
| 安装配置 | 按地图/相机保存；地图 up 默认来自正立参考相机的稳健估计，也可一次性手工设置；不是标定级外参 |
| 执行接口 | `local_motion.py` 分离速度、转向、局部目标、反馈、避障证据、停止/减速/绕行及方向范围；默认无传输实现 |

索引、安装设置和任务输出位于当前地图的 viewer sidecar 下 `navigation/`，不进入冻结地图。
`setup.json`、`navigation_index.json`、`task-*/goals.json`、`task-*/guidance_log.json` 和查询证据均可追溯。
修改地图、目标、来源、回放录像、当前位置照片或相机后，需要重新开始任务；晚到结果不能覆盖新任务。

## 实测结果与重要更正

### 已验证的软件功能

- 现有真实地图：58 个注册相机、3549 个点；自动生成 **56 条有向连接**，保留缺失注册帧两侧的两项断点。
- 白球：保留原焦距修复。常驻后端重复得到 **506/1568 内点**，与原单图流程一致；不是精度提升实验。
- 从白球实际支持点的参考观测中自动筛出 **10 个较优观察候选**；不手填 XYZ。
- 同一采集会话的真实帧功能检查：可生成 10.2544 map_units 路线；关闭必经边 auto:30 后为 no_path。
  **该项只验证真实图上的规划算法，不是独立查询验收。**
- Chrome 中实际跑过逐帧定位、前进/转向提示、丢失恢复、观察区与后续图像几何复现流程。
  这次端到端成功所用录像后经审计确认与建图同源，因此不能计入独立验收。

### 必须撤回的早期判定

本轮最初的 `results/navigation_20261016/independent_replay_v1`、`independent_replay_v2`
以及对应第一次 Chrome 任务，错误地仅凭 PNG 文件哈希判断独立性。
进一步解码审计发现：该录像与地图有 **59 帧像素一致**。原文件和日志保留用于追溯，不覆盖、不删除；
名字中的 independent 不再代表其审计结论。**这些结果一律降为“同源真实帧功能检查”。**
现已新增像素级拒绝及回归测试；该录像在“独立录像回放”入口会被拒绝。

### 真正独立采集会话

另一个 camera6 采集会话（955 帧记录）与建图参考帧无文件/像素重合。
按 4 秒源读取间隔抽查 **16 帧**，**13 帧定位成功、3 帧证据不足**；成功位姿均未合法接入路线。
抽查前几个成功位置到最近历史线段约 1.04–1.10 map_units，典型参考间隔约 0.1443 map_units。
未为获得路线而放大接入门槛或手填位姿。结果保存在 `independent_session_v4/`。

这里的 13/16 是这个小样本的计算状态统计，**不是系统定位准确率或泛化成功率**。
首帧冷启动约 4.45 秒，该轮定位耗时中位数约 1.21 秒；它是计算耗时，不是传感器曝光到显示的端到端延迟。
实时预览读取检查返回“没有可用新鲜画面”，因此本轮没有实测现场遥控行走时的实时闭环。

## 可用性与尚未完成的能力

- 会话级设置后，新目标需要上传、打开、拖框、计算、开始五个操作；复用已算目标只需开始。
- 普通任务手写 JSON：0；正常路段逐边人工审核：0；手选 XYZ：0。
- 本次真实独立序列的自动接入为 0/16；不能用同源演示填充这个指标。
- 目标观察区自动确定：白球样本 1/1，不能外推到多目标数据集。
- 独立成功路线的首次生成时间、实时曝光到显示延迟、现场恢复率：尚未测得。
- 不具备自由空间接近能力；偏离路线较远时只显示位置并要求回到已知路段，不画一条直线当作可走路径。
- 暂不跨越缺失注册段；尚无经实际证据验证的补桥，不自动连接多次路线。
- 当前实现仍要求可复核的 supported 目标；弱几何历史观察目标、多实例候选交互没有在本轮扩展。
- 不含新局部跟踪后端；目前是常驻 hloc 局部子图 PnP＋全局回退。
- 原生主视觉库没重装；同时开两个 GPU 定位进程曾触发显存不足。验收串行运行；不要并行启两套常驻服务。

## Go1 控制链审计

本机 `go1_hri/gateway/unitree_adapter.cpp` 使用 mode=2、gaitType=1；
`forward_stop_profile.cpp` 与 `guarded_forward.py` 的已核验路径限制 vy=0、yaw=0。
这证明有速度接口代码和直行保护，**不能证明当前固件已开启避障，也不能证明受控转向已验收**。
本轮没有连接机器人读取当前固件，因此当前固件/避障状态仍未知。

官方 [Go1 comm.h](https://github.com/unitreerobotics/unitree_legged_sdk/blob/go1/include/unitree_legged_sdk/comm.h)
把 gait=4 列为 trot obstacle，而 mode=3/4 的位置/路径字段仍标为 reserve。
社区 [unitree_driver.cpp](https://github.com/snt-arg/unitree_ros/blob/master/src/unitree_driver.cpp)
展示了避障步态配合速度控制，其构造流程还会自动站起；本轮仅阅读，未实例化或运行。

LocalMotionAdapter 是可核验能力边界，当前没有真实传输实现，submit 明确拒绝。
策略函数联合任务状态、实时/尺度/坐标、单一仲裁、新鲜反馈、避障证据、停止能力和当前授权计算 execution_permitted，
不是未来模式永久写死 false，也不是把一个勾选框直接翻成 true。
目前 UI 只有 shadow_guidance；受控转向适配、避障反馈、局部目标、硬件停止接管仍需独立现场工作。

路线/跟随职责分离参考了 [Nav2 Route Server](https://github.com/ros-navigation/navigation2/tree/main/nav2_route)，
没有安装 Nav2。也阅读了 [ViNT](https://general-navigation-models.github.io/vint/)
与 [NoMaD](https://general-navigation-models.github.io/nomad/)，未下载模型或替换现有几何技术路线。
