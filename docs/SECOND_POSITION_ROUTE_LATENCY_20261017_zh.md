## 结论先行

本轮基于 `codex/evidence-viser-route-preview` / `42eb10d` 增量修改，只读取保存数据，没有连接 Go1、采集新画面或发送运动命令。

- 已修复同一观测局部失败后全局重试的重复特征提取、重复匹配及反复读取 PnP 输入问题；保留完整证据，减少 JSON 格式化开销。
- 第二位置接不上路线的直接原因是**已通过定位的相机中心，超出已有历史路线的接入范围**。不是界面不显示位置，也不是第104帧旧断点重新出现。
- **没有把第二位置强行接通。**现有证据不支持吸附最近路段或添加当前位置到历史路段的可通行连接。实际偏离与地图/标定误差的物理成因，仍缺位置真值与相机标定来最终区分。
- 200张真实保存照片重算后，位姿、定位状态、支持参考图与上一轮逐条一致；第二位置仍18/18 `off_route`。这是离线回归，不是新移动验证。
- 耗时得到改善，但**没有全部消除超过3秒的慢帧**：第二位置最慢3.51→2.83秒；182条移动记录最慢4.70→3.54秒，其中仍3条超过3秒。实时门限仍为3秒，这些帧在实时运行中不会因本轮修改而获得豁免。

### 排查结果

1. 图中原生节点的变换矩阵与冻结模型完全一致，所有边端点与所属节点位置误差为0；没有发现轴交换、转置或界面偏移。
2. 第二位置最近历史路段主要位于建图录像的第192～208帧附近。18张照片距最近路段约0.641～0.826 `map_units`，接入限值为0.288644；已有跟踪的退出缓冲也只有0.360805。
3. 距离偏差在估计水平面上为0.635～0.819，沿估计竖直方向为0.079～0.123。不是仅仅站立高度不同。这个竖直方向来自地图相机姿态，不是外部重力真值。
4. 第一张第二位置照片对192、200帧有真实几何支持，最近候选的朝向一致性约0.920；同时支持两端且朝向一致性约1的另一条候选仍因距离被拒绝。不能把它解释成“只缺参考图”或“只需去掉朝向条件”。其他照片可能同时缺少最近边端点支持，但距离已足以拒绝全部18张。
5. 18张照片采用的位姿，其有效点重投影误差中位数为1.57～2.11像素。如果只把相机中心强移到最近历史路线、保持当前旋转和内参，中位误差变成55.70～87.89像素。这个反事实只用于说明**直接吸附会破坏现有图像证据**；不是重新优化后的位姿，更不是独立定位真值。
6. 重新解码原始录像12.2～14.8秒，每约0.13秒取帧；排除已参与建图的图像后，15张额外历史帧中13张通过定位、2张证据不足。通过的历史帧与18个第二位置的最小点间距仍约0.630 `map_units`。没有根据这些离散样本插值或补边，也不能据此断言未观测间隙里的每一点；但没有发现足以解释偏差的漏采弯道证据。

原始录像为真实camera6录像，不是把无序照片重编码的视频。补帧只做历史诊断，未冒充独立当前照片、未加入导航图。

另对第二位置第1、9、18张做内参敏感性检查：仅在独立实验中固定为地图自估计内参，位置变化分别0.0295、0.0369、0.0119 `map_units`，三张仍为 `off_route`。这不支持“只需把地图内参复制给查询就能接入”的解释；地图自估计内参并非真实标定，生产默认值没有改变。

### 能确定和不能确定的事

能确定软件拒绝发生在距离条件，已有历史路径没有为这些位姿提供合法接入。画面与几何更支持“本次到转角前的位置与建图时的转弯轨迹不重合”；但无真实标定、米制尺度和外部位置测量，不能把这个推断写成已证明的机器人实际偏离距离，更不能把 `map_units` 当米。

后续需要时，再由用户安排连续的新观察：在已能关联的历史位置附近开始，观察移动到第二位置前哪一帧开始离开已有轨迹；或者提供真实相机标定来复核几何。不是要求逐边审核、每次手填XYZ或启用运动控制。本轮没有要求用户移动，也没有自动录制这些数据。

## 2. 加速内容与不变项

`ResidentLocalizer` 仍只持有一套SuperPoint和LightGlue，沿用常驻hloc/PyCOLMAP。

- 一次 `localize()` 内建立短生命周期复用区，局部/全局重试共享；结束、异常都清空，不跨观测复用当前照片。
- 特征提取按实际处理图字节哈希与完整提取配置区分；缓存的是掩膜处理前的原始特征。每次仍在独立文件中施加掩膜，避免把已经过滤的特征当成原图特征。
- 匹配按实际过滤后的所有特征数组、形状、类型与匹配配置区分，只重用重复图像对；新参考图照常匹配。查询张量每组只搬运一次，不减少关键点或参考候选。
- PnP输入按固定版本hloc的顺序、`+0.5`像素约定、歧义3D对应和数据库偏移组装；查询关键点、各参考图的匹配索引只读取一次。每个候选仍实际求解，逐候选独立相机，所有原门限与参考组一致性检查保留。
- 冻结模型的共视分量按有序参考ID缓存，最多32组；这不是导航路线，未用共视关系补可通行边。
- 常驻查询的证据JSON改为紧凑格式。字段、内容摘要、原图/特征/匹配/地图绑定和验证均保留；研究CLI默认仍可读缩进。
- 记录提取、匹配、共视、PnP输入与求解、行证据导出、封装写盘、验证、总耗时和复用次数；工作线程/界面采用日志也携带这些统计。

保持不变：PnP至少6对、6内点、0.25内点率、4像素阈值；参考回退预算20；路线初次接入2×typical_step、既有跟踪2.5×；真实当前3秒时效；目标身份、来源绑定、分量、反向与观察区检查。没有修改 `navigation.py` 的关联/规划算法或任何冻结图。

探索中试过复用同一观测内的PnP结果，但它改变后续随机求解过程，使移动事件130变为歧义拒绝，因此**已撤掉且不在发布实现中**。`timing_v2` 是相机枚举序列化失败的未完成实验；`timing_v3` 是撤销前的探索记录，都不能作为发布结论。

计时为离线单机处理墙钟时间，含证据落盘与验证，不是曝光到显示延迟，不代表硬实时保证。对照运行不是同时进行的硬件基准实验，会受CPU/GPU调度与磁盘缓存影响。常驻实例只加载2个网络（1×SuperPoint、1×LightGlue），预热约4.47秒，预热照片不作为当前位置。

算法结果：18张第二位置均定位通过且均拒绝接入；182条均定位通过，121条关联、1条分支歧义、60条未接入。状态机仍只有120条离线方向（119向前、1右转）；第126条即使几何上可关联，仍被二次观测确认逻辑拒绝立即切换分支。不能把这些数字叫导航成功率。

全套软件回归：**563项通过，0失败、0错误、0跳过**。新增8项聚焦复用、索引、相机独立性与缓存隔离；补强现有工作线程/界面测试。先观察新增行为失败再修改；没有用测试数量代替实机验证。

新增真实链路复用测试使用已安装的可选hloc/vision环境；缺该环境时明确跳过，不因此要求纯软件使用者安装第二套视觉环境。上述0跳过是本机完整环境的实际结果。
