# 第二位置路线接入修复与离线复核

日期：2026-10-21。分支：`codex/evidence-viser-route-preview`。

## 结论先行

第二位置的直接失败原因仍然是“定位成功，但没有合法历史路线接入”，不是定位器完全失效，也不是可以通过增大接入距离解决。新代码补上了真实连续观测的路线支路导入能力：支路只由已核验的定位证据、源序号和读帧时间生成；它可以在不修改冻结地图的情况下连接两个有真实观测的历史边锚点。

用已有往返录像做离线验证时，成功导入了一段 50 个样本的有向真实观测支路，并从支路规划到白球参考观察位姿；结果仍是 `execution_permitted=false`，没有连接机器狗或发送运动命令。

第二位置保存区间仍没有被强行接入：55 个检查样本中 45 个定位通过、10 个参考一致性歧义；只有 18 个相邻定位样本间隔不超过 0.5 秒，区间前后没有合法的同源历史边锚点，不能凭空间近邻补一条入口或出口边。因此这份旧保存数据可以证明软件现在能正确导入“有锚点的连续支路”，但不足以证明第二位置本身已经形成可规划路线。

## 修改内容

- 新增 `src/go1loc/navigation_trace.py`。
  - 从密封的 `localization_result.json` 和 `query_evidence.json` 重新读取姿态与参考证据。
  - 校验地图/分量、原始观测身份、camera、源会话、查询哈希、证据哈希、源序号和读帧时间。
  - 只连接时间递增且间隔不超过 0.5 秒的实际定位观测；不插值、不填 XYZ、不把 `verified_continuous` 改成 true。
  - entry/exit 锚点的投影由旧路线边重新计算，sidecar 中的投影只作一致性检查。
  - 新增路线默认单向、相机路线预览、`execution_permitted=false`。
- `navigation_io.prepare_index()` 在导航 sidecar 发现 `route_trace_import.json` 时自动核验并载入；没有该文件时旧流程不变。
- 新增回归 `tests/test_navigation_trace.py`，覆盖：有锚点支路可规划、无锚点仍断开、时间间隔/身份/证据/锚点错误拒绝。

## 还缺什么才能真正修通第二位置

需要重新采一小段独立 camera6 录像，覆盖：

1. 第二位置前最后一个能够通过正常 `associate_route` 的历史边观测；
2. 连续离开旧路线、停到第二位置并保持视角；
3. 返回旧路线或抵达另一条已知历史边的连续观测。

中间不能只保存每秒一张、不能跨越歧义帧或大于 0.5 秒的观测缺口。新录像只需用于路线支路导入，不需要重建冻结地图；程序仍只做影子引导，不发送运动指令。
