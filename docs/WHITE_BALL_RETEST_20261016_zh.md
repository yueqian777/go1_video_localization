# 白球照片定位复测：失败反馈与查询相机参数

日期：2026-10-16。基线：`codex/evidence-viser-route-preview` / `e3c45bc`。
继续使用 hloc / SuperPoint / LightGlue / PyCOLMAP；未重建旧地图、未安装环境、未连接 Go1。

## 结论

两处软件问题已修复。使用同一张原始白球照片重新求解后，照片位姿通过既有门槛。
**原来的大框仍存在多个三维候选；明确缩小为球体附近的框后，得到 8 个三维支持点。**
它们对应 6 个不同的查询像素位置，并非 8 个独立像素测量。历史参考画面中可对上白球表面及轮廓附近。
部分轮廓点靠近背景边界，不能据此声称精确球心、完整球面或已知米制精度。

## 1. 根因及修改

### 查询相机参数

旧代码在没有标定时调用 `infer_camera_from_image`，获得猜测焦距 1536 px。
当前环境 PyCOLMAP 4.2.1 默认既不在位姿估计阶段估计焦距，也不在优化阶段调整焦距。
因此这个初值被固定使用，导致此照片只能接受 77 / 1568 个二维—三维对应。

修改 `localization.py`：

- 无已知内参：显式开启 `estimate_focal_length` 与 `refine_focal_length`。
- 有手动内参或可靠标定：保持固定，不自动覆盖、重复去畸变或改动额外畸变参数。
- 不因图像分辨率相同就复制地图相机参数，不假定两者属于同一物理相机。
- 保存初始参数、估计策略、每个候选的实际参数以及原有验收阈值；检查估计参数为有限合法值。

本次估计得到 SIMPLE_RADIAL `[616.971648, 640, 360, 0]`；地图自身估计焦距为 617.259532 px。
两者接近是诊断依据，不是相机实测标定或同一设备的证明。

### 完成状态与失败提示

旧 `load_object()` 在照片定位失败时直接抛出 `object_query_not_localized`，跳过选框恢复和具体反馈。
加载过的失败查询目录还会被默认复用，导致用户重复计算仍拿到旧失败证据。

修改 `viser_viewer.py` / `viewer_text.py`：

- 区分“照片定位未通过”“照片已定位但框内支持不足”“框内有多个三维候选”和“目标已有三维支持”。
- 已完成的负结果先验证绑定，再保留有效选框，显示实际内点数、内点率及记录中的阈值，允许重新计算。
- 失败不保留旧目标/路线，不把后台计算完成误报成定位成功。
- 默认重新求解照片；只有显式勾选“复用已载入且定位成功的证据”才复用，失败查询不可复用。
- 显示实际采用的查询相机参数及来源；简短提示不混入文件路径、原始错误码或 `None`，完整信息仍在诊断详情。

## 2. 实际复测，不降低门槛

真实输入：用户提供的 1280×720 白球照片。

| 照片位姿 | insufficient_evidence | localized | 复用左列新成功证据 |
| 内点 / 对应数 | 77 / 1568 | 506 / 1568 | 同左 |
| 内点率 | 4.9107% | 32.2704% | 同左 |
| 要求的内点率 | 25% | 25% | 25% |

平均误差只在各自被接受的内点上计算，不能把以上比例/误差变化当作定位精度或泛化成功率。
始终保持原阈值：至少 6 个对应、6 个内点、内点率 0.25、重投影门槛 4 px；对象至少 3 点，默认尺度自适应聚类。

原框为 `[355.337339, 551.217167, 531.247470, 720]`，包含球、黄色底座及周边背景。
重算后有 33 个框内内点对应、32 个不同地图点，两组达到要求的候选分别含 28 点、3 点；没有擅自取最大簇。

紧框对照为原图像素 `[402, 579, 494, 674]`。这是明确改变二维选框的独立对照，**不是原框成功**，未手填三维坐标。

可见表面代表位置约 `[7.51725, -0.10041, 4.59896]`，单位 `map_units`；30 个参考帧参与支持。

逐点图核验使用查询真实匹配像素和原生地图保存的参考观察像素，并非根据期待位置绘制假点。
抽查 `frame_00000224.png`、`frame_00000384.png`、`frame_00000456.png`：白球区域有一致支持，但部分轮廓/背景交界点仍有语义歧义。

## 3. 网页如何使用

1. 选择照片，打开原图，用鼠标贴近目标轮廓框选；检查绿框预览。
2. 没有真实标定时保留高级内参为空，点击“计算目标位置与证据”。默认会重新定位照片。
3. 查看结果提示。照片失败时先检查清晰度、重叠视野和内参；多个三维候选时检查是否框入背景。
4. 相机参数来源及本次值在“高级：掩膜、标定与支持点参数”中。
5. 返回地图查看黄色目标支持点；绿色相机是历史观察位姿，紫色相机是目标照片位姿，不是机器狗当前位置。
6. 只有对同一原图重新调整框、且明确希望沿用已成功定位的证据时，才勾选复用。

本次已将紧框结果通过原有校验加载到运行中的 Viser 服务。后台确认 `model/query/support` 场景组存在，未生成路线。
该记录验证服务端实际状态，**不是浏览器截图验收**。
