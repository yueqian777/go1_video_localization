# 找物边界修复与新影子引导验证（2026-10-17）

## 结论与版本

继续分支 `codex/evidence-viser-route-preview`，本轮基于 `5b069bb07886e6c64e73f4832817e437bec39439` 增量修改。原地图、白球目标、旧45条记录和此前180条静止记录均保留；没有重建导航架构、重装视觉环境或接通运动。

**软件边界已修复，但新的连续移动验证未通过第二位置。** 用户遥控前进并确认“第二位置已停”，但未注意网页方向。不能把120条方向输出写成120次正确导航，不能宣称完成到白球的移动验收。

最终采集断开、引导暂停；本轮没有运动命令。后续现场控制另行通知，不需要用户继续站在旁边等待。

## 1. 最小复现与修复

采用测试先失败、再修复的流程。`tests/test_navigation_boundaries.py` 最初9项中7项失败，包含相机反向导致 `off_route`、仅因方向插入顺序选错边、已在目标A却先搜索B/C而失败。修改后9项通过。

### 反向路线

- `associate_route`关联物理路段；`plan_guidance`在该路段**已存在且有声明**的合法方向之间按目标/路线代价选择，不按字典插入顺序选方向。
- 保留历史相机真实光轴。相反视角需当前PnP同时支持两端参考且相机上方向兼容；不虚构反向照片，不删除全部朝向门禁。
- 不自动新增反向边。缺少反向通行声明时明确 `reverse_travel_not_enabled`；缺反向视觉证据时 `opposite_view_evidence_insufficient`。
- 合法路线在身后时提示“请先转身”，不会发转身命令。反向边继续标 `reverse_visual_support=false`。
- 封闭一个物理路段时，其明确配对的反向边也封闭，不能绕过封路。其它相近路段/路口边不因此一起封闭。

本次真实地图仍为 `reverse_allowed=false`，没有替用户勾选可反向。反向结论来自已知几何合成回归，尚非现场反向实测通过。

### 已经在目标观察区

在路线搜索之前判断：同地图/分量、有效实测位姿、正确目标的至少3个几何匹配、到合格目标观察位姿不超过一个 `typical_step`、光轴点积至少0.5。符合时进入观察区，不要求先找到一条离开再回来的路。

后续**更新序号与源时间的新画面**仍需满足同一观察区和目标几何支持才能确认；离开、暂停、过期或使用目标原照片会清除确认链。目标原图身份由已核验的原图哈希绑定，不比较文件名。远处看见目标、朝向不符、无目标支持、旧目标照片均不能结束任务。

只输出相机观察区，不把球心、机身位置或足步位置混为一谈；距离仍为 `map_units`。

## 2. 预热、时间记录与显示

`ResidentLocalizer.warmup()`使用冻结参考图运行**同一实例**的SuperPoint/LightGlue，预热不作为当前位置或跟踪证据。旧worker退出后复用常驻实例，不并行加载第二套GPU模型。预热完成后才读新帧，并拒绝接收时间早于预热完成的源图。

记录分层如下：

| 文件/字段 | 含义 |
| --- | --- |
| `warmup.json` | 预热开始/结束、是否复用、模型加载数 |
| `parameters.json` | 每个运行的地图、安装声明、数值阈值与定位配置 |
| `queries/worker_events.jsonl` | 接收/提交、推理起止、待处理帧替换、任务代际失效与丢弃原因 |
| `guidance_events.jsonl` | 每个完成结果、来源时钟、计算结果目录、采用/拒绝原因及界面服务端更新时间 |
| `ui_states.jsonl` | 两次计算之间的显示状态变化，可计算方向有效持续时间 |
| `guidance_log.json` | 暂停/取消/结束时保存的兼容快照；运行中以JSONL为准 |

`received_monotonic`是电脑收到源帧的时间，**不是传感器曝光时间**。`ui_applied_monotonic`是Viser服务端应用场景状态的时间，**不是浏览器绘制确认**。尚无曝光到显示端到端延迟测量，不能把推理耗时叫作这一延迟。实际Chrome截图另存本地。

没有放宽3秒时效。预热后首次全地图匹配仍可能超时：v1第一条虽已定位，但接收到界面约3.046秒，被拒绝。预热不等于所有全局重定位都足够快。

新现场失败还复现了“位姿质量不足被过期提示覆盖”的可读性问题。增加单独定位诊断与回归：同时保存位姿质量和超时，不只提示检查相机网络。新运行已实测显示“本次照片定位失败：位姿质量不足”；真正断开后切换到断流提示。

### 现场剩余项与原因边界

| 场景 | 本轮结论 |
| --- | --- |
| 起点静止及原路线前进到第二位置 | 有新数据；未连续稳定通过 |
| 定位成功但路线未接入 | 真实出现4次；未强行给方向 |
| 实际转角、小幅偏离再返回 | 未进行；第二位置定位失败先阻断该序列 |
| 进入观察区、已经靠近白球 | 软件回归通过，真实新观测未完成 |
| 目标在身后 | 软件回归通过，真实测试未完成，地图未授权反向 |
| 暂停/断流/封边 | 实际暂停和无方向时断流已观察；新移动中的封边及恢复未完成，旧45条离线封边仍返回no_path |

已定位的直接拒绝原因是距离/参考支持不满足与随后PnP质量不足。深层原因**还不能唯一归因**：第二位置的局部地图几何、场景/视角变化、错配/重复纹理及未标定相机模型仍需区分。重启新定位器后全图独立定位仍失败，说明不只是旧局部参考缓存的问题。

下一步限定在现有链路：对保存失败帧检查各参考匹配与重投影分布，核实camera6固定安装、分辨率和可验证标定；在新输出目录做有记录的内参/参考集合对照。不要改质量门槛或接入倍数来掩盖错误，不要手填XYZ。离线原因收敛后再安排新编号现场序列；这些后续诊断/移动项目尚未完成。

## 6. 真实执行仍缺什么

`local_motion.py::LocalMotionAdapter.submit()`仍明确抛出未安装适配器错误，`invalidate()`不发命令。本轮没有新增传输。

若另行开展真实执行，需要独立实现并验证：现有网关的速度/转向传输、单一命令仲裁与遥控接管、新鲜状态反馈/超时撤销、米制尺度及相机到机身外参、转向/停车能力，以及有实测证据的避障状态和前侧距离接口。影子方向不等于可执行子目标，不能仅把 `execution_permitted` 改为 `true`，不能自动部署Go1控制器或调用保留的绝对位置/路径接口。
